# PM 4 阶段差异

## 阶段 1：想法验证（idea-validate）

**PM 心态**：「这个方向靠谱吗？会不会太拥挤？」

**搜索策略**：
- 广撒网，4 源全开
- 关键词扩展到 5-8 个近义词
- 不限 GitHub 语言、地区

**评分权重**：
- 相近度 60%（找"在做类似事情"的）
- 成熟度 40%（看冷热 - star/评论/媒体曝光）

**报告重点**：
- 「市场拥挤度」判断（10+ 直接竞品 = 红海；<3 = 蓝海）
- 「空白点」识别（没被满足的用户群 / 没被解决的具体场景）
- 「早期信号」（新冒头但还没成气候的项目）

**典型发现**：
- 「已有人做但都没做大」→ 可能是伪需求
- 「小众但有付费用户」→ 可能是 niche 机会
- 「所有人都在做但都难用」→ 体验升级机会

---

## 阶段 2：竞品对标（competitor-analysis）

**PM 心态**：「明确方向了，看最像的 3-5 个怎么打的」

**搜索策略**：
- 先广搜找到候选池（10-15 个）
- 再深挖 Top 3-5（必须读产品官网/定价页/用户评论）
- 商业产品库优先（Product Hunt、App Store 评分/评论）

**评分权重**：
- 相近度 80%（只关注直接对手）
- 成熟度 50%（含商业模式信号）

**报告重点**：
- 功能对比矩阵（横轴：功能；纵轴：竞品）
- 定价模式（订阅/一次性/免费增值）
- 用户口碑（App Store 评论、Reddit 抱怨点）
- 商业模式信号（融资、招聘信息、营收估算）

**典型发现**：
- 「所有竞品都没做 X 功能」→ 差异化机会
- 「竞品 A 的用户都在抱怨 Y」→ 切入点
- 「竞品 B 融了 Z 亿但增长慢」→ 可能有泡沫

---

## 阶段 3：功能灵感（feature-inspiration）

**PM 心态**：「我要做 X 功能，找参考实现」

**搜索策略**：
- GitHub 优先（找开源实现）
- 技术博客次之（找工程实践）
- 不需要扫商业产品

**评分权重**：
- 成熟度 70%（要能跑、能参考）
- 相近度 50%（具体功能点匹配即可，不强求产品同构）

**报告重点**：
- Top 开源实现（star、活跃度、文档质量）
- 技术栈选择（用什么语言/框架/数据库）
- 实现思路对比（不同实现的 trade-off）
- 可借鉴的交互模式

**典型发现**：
- 「GitHub 上有现成的 X 库」→ 拿来即用
- 「A 用 Redis、B 用 SQLite」→ 性能 vs 简单 trade-off
- 「业界通用做法是...」→ 降低决策成本

---

## 阶段 4：赛道扫描（market-scan）

**PM 心态**：「季度/半年盘点，看整个市场长什么样」

**搜索策略**：
- 最广（4 源全开 + 行业报告）
- 按子赛道分类（不是按相近度）
- 时间维度：近 1-2 年的新项目

**评分权重**：
- 分类完整度优先（不能漏掉主要玩家）
- 成熟度次之（要识别头部和尾部）

**报告重点**：
- 市场地图（横轴：用户群；纵轴：核心价值）
- 头部玩家份额（top 5 占多少）
- 趋势信号（媒体讨论热度、融资节奏）
- 子赛道空白点

**典型发现**：
- 「某子赛道完全没人做」→ 可能是下一个机会窗口
- 「头部都在加同一功能」→ 行业共识
- 「去年火的概念今年没人提」→ 泡沫破裂信号
