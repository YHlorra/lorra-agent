# Reference Projects - PM 参考项目搜索

## 何时用

PM 在动手前需要摸清"市面上在做什么"。触发条件：

- 想法验证：「我有个模糊想法，先看看有没有人做」
- 竞品对标：「明确方向了，深度对标直接对手」
- 功能灵感：「要做某功能，找最佳实践参考」
- 赛道扫描：「季度/半年盘点，看市场地图」
- 通用：「帮我搜下类似项目」「查下 GitHub 上有没有人做 X」

## 不做

- 不做技术架构设计、不写代码
- 不替代用户访谈和 PMF 验证
- 不预测成功率、不评判商业价值
- 不做 UI/UX 设计稿
- 不写 PRD（只整理「参考素材」给 PM 二次加工）

## 工作流

### Step 1: 解析输入

从用户输入中提取：

| 字段 | 来源 | 示例 |
|------|------|------|
| 核心关键词（中英） | 用户描述 | 「AI 笔记」/ "AI note-taking" |
| 目标用户 | 用户描述或追问 | 「独立开发者」「知识工作者」 |
| 解决的问题 | 用户描述 | 「碎片信息整理」 |
| PM 阶段 | 用户指定或追问 4 选 1 | 想法验证 |

追问 1-2 个问题就够，不要问完。

### Step 2: 多源并行搜索

四源并发扫描，详见 `references/search-strategy.md`：

| 源 | 工具 | 适合什么 |
|----|------|----------|
| GitHub | `gh` CLI / `gh_grep_searchGitHub` | 开源项目活跃度、技术实现 |
| Web | `webfetch` / `websearch_web_search_exa` | 媒体报道、产品发布、博客 |
| 社区 | `agent-reach` skill | V2EX / HN / Reddit / 少数派 / 即刻 的真实讨论 |
| 商业产品库 | `webfetch` / `websearch` | Product Hunt / App Store / Chrome Store |

每源跑 1-2 个核心 query，结果去重。

### Step 3: 评分与分类

每个候选项目打两个分（0-10）：

- **相近度**：跟用户想法的契合度（功能/用户/问题）
- **成熟度**：项目状态（活跃度/用户量/收入信号）

按 4 阶段调整权重，详见 `references/pm-stages.md`。

四象限分类：

| | 高相近 | 低相近 |
|---|--------|--------|
| **高成熟** | 直接竞品 | 间接竞品 / 灵感来源 |
| **低成熟** | 早期项目 | 失败案例（教训价值） |

### Step 4: 输出 Markdown 报告

模板见 `assets/report-template.md`，结构：

1. 概览地图（一段话 + 关键词云）
2. 四象限总览表
3. 重点深扒（Top 3-5）
4. 失败/废弃案例（如果有）
5. 差异化机会（基于分析推断）
6. 二次深挖建议

### Step 5: 收尾追问

- 「需要再深挖某个项目吗？」
- 「要不要换个阶段视角再扫一遍？」
- 「要不要把这些沉淀成 `references/` 下的项目档案？」（v2 持久化）

## 4 个 PM 阶段差异

详见 `references/pm-stages.md`，核心差异：

| 阶段 | 搜索广度 | 评分侧重点 | 报告重点 |
|------|----------|------------|----------|
| 想法验证 | 最广 | 相近度 > 成熟度 | 「拥挤度」「空白点」 |
| 竞品对标 | 收窄到 3-5 个 | 成熟度 + 商业模式 | 功能/定价/口碑 |
| 功能灵感 | 收窄到技术实现 | 成熟度（要能跑） | 开源实现参考 |
| 赛道扫描 | 最广 + 分类 | 分类完整度 | 市场地图 + 趋势 |

## 搜索策略细节

详见 `references/search-strategy.md`，包括：

- 每源的 query 模板
- 关键词扩展（中英 + 同义词）
- 噪音过滤规则
- 评分时的硬阈值

## 报告模板

详见 `assets/report-template.md`，可直接复制填充。

## 边界

- 单次会话内工作，不做 v1 持久化（user.json 跨会话留到 v2）
- 搜索深度优先于覆盖广度：宁可少而准，不要多而杂
- 不主动推荐商业服务、不做投资建议
- 中文输入 → 中文输出；英文输入 → 英文输出；混合 → 中文为主 + 原文保留
